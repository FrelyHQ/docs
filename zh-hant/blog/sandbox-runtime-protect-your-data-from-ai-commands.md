讓 AI 在你的電腦上執行 shell 指令很有用。它可以安裝依賴套件、執行測試、讀取日誌、修復 build。但這也意味著：一個不是你寫的程式，受著你沒有審閱過的文字驅動，以你的用戶帳戶執行。

預設情況下，該帳戶可以讀取你的 SSH 金鑰、雲端憑證、套件倉庫的 token，以及瀏覽器設定檔。一個指令不必帶有惡意也能造成損害。藏在網頁或 issue 留言裡的提示注入（prompt injection），已足以令一個看起來完全正常的指令讀取秘密並傳送出去。

在每個指令前問一句「你確定嗎？」解決不了問題。人們會批准自己未能完全看懂的東西。更好的做法，是令危險的事情預設變得不可能，並在真正需要時讓人打開一道窄門。這正是沙盒的用途。

## srt 是甚麼

`srt` 是 Anthropic 的開源沙盒執行環境（`@anthropic-ai/sandbox-runtime`）。它為 Claude Code 而建，可以作為命令列工具或函式庫使用。它會把任何行程，以及該行程啟動的所有東西，包在由作業系統強制執行的檔案與網絡限制之內。它既不需要容器映像，也不需要虛擬機器。

它自己的 README 稱它為 beta 研究預覽版，所以請把它當作一塊堅固的建材，而不是一份已完成的保證。

### 它如何限制檔案

檔案規則說起來很簡單：

- **預設允許讀取任何地方。** 你用 `denyRead` 列出要隱藏的位置，例如你的憑證資料夾。
- **預設拒絕寫入任何地方。** 你用 `allowWrite` 列出指令可以寫入的位置，通常是專案資料夾和一個暫存目錄。`denyWrite` 的效力高於 `allowWrite`，所以你可以在一個允許的資料夾之中，劃出一個受保護的檔案。

讀取方面採用的是拒絕清單，而不是允許清單。這樣做很實際，因為工具需要讀取很多系統檔案，但這也代表沙盒只會隱藏有人想到要列出來的東西。

### 它如何限制網絡

預設情況下，完全不允許任何網絡存取。指令只能透過在沙盒外運行的代理伺服器連上網絡，而這些代理伺服器會決定允許哪些網域。

- **macOS：**指令在一份自動產生的 Seatbelt 設定檔（`sandbox-exec`）之下執行，該設定檔只允許與本機代理連接埠通訊。
- **Linux：**指令在 bubblewrap 之下執行，其網絡命名空間已被移除，因此唯一的出路，是透過以掛載進沙盒的 Unix socket 連接的代理伺服器。

HTTP 和 HTTPS 經 HTTP 代理伺服器處理。其他 TCP 流量經 SOCKS5 代理伺服器處理。兩者都會執行網域允許與拒絕清單。Unix socket 預設被封鎖。

### 為甚麼這是個好方法

這些限制存在於作業系統之中，不建基於 AI 的良好行為，也不是一份指令名稱清單。指令可以被改寫、包進指令碼（script），或加以混淆，它依然無法讀取沙盒隱藏的資料夾，也無法寫入獲分配資料夾以外的地方。同樣的規則適用於每一個子行程。

## srt 做不到的事

沙盒不是魔法護盾。誠實面對限制很重要，因為這些限制決定了你可以放心把甚麼交給它。

- **它的嚴密程度取決於其設定。**如果網絡允許清單是開放的，指令讀得到的任何東西都可以被送出去。如果某個秘密不在拒絕清單上，沙盒就不會隱藏它。
- **Beta 軟件。**專案自己也是這樣說，而且它的選項可能會改變。
- **平台差異。**它支援 macOS 和 Linux。在 Linux 上需要 bubblewrap、socat 和 ripgrep。srt 對 Windows 的支援屬 alpha 階段，而 Frely CLI 不會在 Windows 上執行沙盒內的指令。
- **有些選項會刻意把它削弱。**允許 Unix socket、巢狀沙盒或 Apple Events，每一項都會打開一條繞過隔離的途徑。README 已就這些提出警告。
- **它限制的是單一指令的行程樹。**它保護不了把密碼交給 AI 的人，也保護不了你自己從沙盒複製出來的檔案。

## Frely CLI 如何使用 srt

Frely CLI 讓你用你的 AI 控制一部電腦：AI 提出請求，CLI 在你的裝置上執行指令。Frely CLI 為遠端 AI 用戶端執行的每一個指令，都會先經過 srt。以下根據 CLI 的原始碼，說明實際運作是怎樣的。

### 預設行為

- **寫入：**指令可以在工作區資料夾和系統暫存目錄之內寫入。僅此而已。
- **憑證資料夾一律隱藏。**CLI 拒絕讀取 SSH 金鑰、AWS、Google Cloud、Kubernetes 及 GitHub CLI 的設定、GnuPG 金鑰、已儲存的 git 憑證，以及套件倉庫 token 檔案（`.npmrc`、`.pypirc`、Cargo 憑證）。Frely 自身的裝置憑證，任何批准都無法將之打開。
- **敏感位置保持寫入保護。**`.zshrc`、`.bashrc` 等 shell 啟動檔案、macOS LaunchAgents，以及憑證資料夾，都受寫入保護。「在我的主資料夾之下寫入」這類寬泛權限並不包括它們。要打開其中一處，必須指明該確切路徑。
- **`.git/hooks` 仍然被封鎖。**hooks 會在沙盒之外執行程式，所以沒有任何批准會將之打開。
- **失敗即封鎖。**如果沙盒無法在裝置上啟動（平台不受支援，或缺少依賴），指令會被拒絕，並附上說明原因的訊息。它絕不會在沒有沙盒的情況下靜靜執行。

### 以狹窄方式要求更多

當指令需要沙盒所隱藏的東西時，AI 不能自行拿取。它會提出請求，由裝置擁有者在 Frely 網站上批准，以 passkey 或驗證器驗證碼確認，而不是在聊天視窗中按下按鈕。請求會列明原因和確切的指令。批准可以窄至單一憑證群組（例如 SSH，但不包括 AWS）、單一快取資料夾，或一個特定目錄。

如果沒有合適的窄項，擁有者可以批准在沙盒之外執行指令。這是最後的選擇，而非預設，而 CLI 的拒絕訊息會推動 AI 先要求最窄的選項。

### 使用 Git 而毋須交出大門

srt 會封鎖對儲存庫 `.git/config` 的寫入，因為 git config 可以令 git 日後在沙盒之外執行程式。這也同時封鎖了 `git push -u`、`git remote add` 等日常指令。

Frely CLI 允許一般指令進行這類寫入，然後再作檢查。它會在指令執行前為工作區內的每個 `.git/config` 複製一份副本，在指令結束後比對，並移除任何新增、且會令 git 執行程式的設定，例如 fsmonitor、credential helper、自訂 pager 或 shell alias。結果會告知 AI 移除了甚麼。指令遺留在背景執行的行程會被終止。

### 從沙盒之內連接網絡

由於 srt 只為 HTTP、HTTPS 和 SOCKS 流量提供路由，像 `ssh` 這類工具需要協助。CLI 會將 `ssh`、`scp` 和 `sftp` 經沙盒的代理伺服器傳送。至於資料庫用戶端和其他原始 TCP 工具，內置的 `frely tunnel` 會在沙盒之內開啟一個本機連接埠。如果你經本機代理伺服器（例如 Clash）連上互聯網，`frely sandbox proxy` 可以讓沙盒使用它。Frely 只會讀取你的代理設定，不會更改它們。

### Frely CLI 對 srt 的使用未涵蓋之處

我們寧可讓你知道邊界所在：

- **對外網絡預設開放。**CLI 不限制指令可以連到哪些網域，令 npm、pip、git 和 curl 得以繼續運作。這意味著保護你資料的是檔案規則：沙盒讀得到的秘密，同樣可以被送出去。保護來自令憑證無法被觸及，而不是來自封鎖網絡。
- **你的主資料夾大部分都可被讀取。**拒絕清單涵蓋為人熟知的憑證位置，並非所有私人內容。你存放在其他地方的檔案（另一個專案中的 `.env` 檔案、筆記、文件），在沙盒中執行的指令同樣讀得到。
- **獲批准的存取就是真正的存取。**如果你批准存取 SSH 金鑰，指令就能讀取那些金鑰。只批准你明白的東西，並優先選用最窄的選項。
- **`.git/config` 的防護屬事後檢查。**它在指令結束後才撤銷危險設定。它檢查的是 git 已知會執行程式的設定，而且它本身也註明了一項限制：在兩個指令之間逃過清理的行程，會在下一次檢查時被截獲，而不是即時。
- **它約束的是指令，不是人。**沙盒限制的是指令可以觸及的東西。它阻止不了你批准不明智的事情，也不能取代鎖定的螢幕或穩固的帳戶登入。
- **srt 仍處於 beta 研究預覽階段，**而 Frely CLI 亦繼承這個狀態。

## 簡短總結

能執行指令的 AI，其安全性取決於圍繞這些指令的牆。srt 在作業系統層面築起這些牆：除了專案之外不能寫入、隱藏憑證資料夾，並讓網絡流量經過一個把關者。Frely CLI 預設把這些牆立著，令打開它們成為一個深思熟慮、範圍狹窄、須經人手批准的步驟，並坦然告訴你它未涵蓋甚麼。

如需沙盒涵蓋範圍的簡短摘要，請參閱[沙盒如何保護你的資料](https://frely.cloud/connect/sandbox/)。
